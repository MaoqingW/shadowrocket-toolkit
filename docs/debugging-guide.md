# 用知乎开屏场景练习调试

本文描述实验步骤。接口地址、请求参数和广告字段以自己的抓包结果为准。

## 观察

1. 让 iPhone 与运行 Proxyman 的 Mac 位于同一可互访 Wi-Fi。打开 Proxyman 的 iOS 实体设备安装向导，在 iPhone 当前 Wi-Fi 的「配置代理」填入向导显示的 Mac IP 和端口。实验期间暂停可能接管流量的 Shadowrocket，记录原网络设置。
2. 按向导安装并在 iOS「证书信任设置」信任 Proxyman CA。先确认 Safari 的请求出现在 Proxyman，再按候选主机名逐个开启 SSL Proxying。若 App 无法经代理访问或拒绝证书，记录现象并停止对该连接的解密测试。
3. 清空本次视图，记录时间、知乎版本、网络与登录状态。重复冷启动，标记何时看见开屏广告。保留同样环境下无广告和打开首页的对照记录。

参考 [Proxyman 实体 iOS 设备配置](https://proxyman.com/docs/debug-devices/ios-device)。

## 定位

用启动时间窗口缩小范围，比较有广告和无广告的请求。对候选项记录 HTTP 方法、主机、路径、查询参数名称、响应状态和 Content-Type。观察 JSON 字段类型、数组结构、图片链接与展示时间是否能对应屏幕现象。区分广告素材、配置与曝光上报。若没有新请求也能展示，单独记录缓存和预取的可能性。

## 假设

写下可证伪的预期，例如「保留同一响应的正常字段，只移除已确认的开屏素材字段，下一次冷启动应跳过开屏并正常到达首页」。准备一份只改该字段的 JSON，保留状态码、业务结构和必要响应头。

## 干预

在 Proxyman 对候选请求右键选择「Tools → Map Local」。用捕获到的响应作为基础，在编辑器修改目标字段，或选择准备好的本地 JSON 文件。限定匹配到已观察的主机和路径，保留正确的 Content-Type，避免沿用与新正文不符的 Content-Length 或 Content-Encoding。再次冷启动，确认 Map Local 命中并返回预期正文。关闭映射再复测一轮，排除广告轮播、缓存等影响。

参考 [Proxyman Map Local 文档](https://proxyman.com/docs/advanced-features/map-local)。

## 验证

- 专用广告域名的全部请求都可丢弃时，用 Rule。与业务共用域名、只有特定 URL 可拒绝时，用 URL Rewrite。响应混有业务数据且必须保留时，用 Script。
- 把已确认的最小条目加到 `modules/my-rules.sgmodule` 对应段内，并在其上方标记知乎。只有需要看见 HTTPS 路径或正文时才配置精确 MITM 域名。
- 恢复 Wi-Fi 原代理设置，关闭 Proxyman 实验映射，恢复 Shadowrocket。测试模块启用和禁用两组，重复冷启动和热启动，同时验证首页、详情、图片和刷新。按实际使用场景复测 Wi-Fi 与蜂窝网络，检查命中日志并记录结果。

## 沉淀

在仓库外保存原始数据。提交最小化、脱敏的 JSON 与分析记录，记录 App 版本、观察条件、请求方法与匹配范围、改动字段、对照结果和回滚方法。删除账号、设备标识、签名参数、Cookie、Authorization 和真实广告素材标识。为缺字段、格式变化和正常内容写回归测试。实验结束后移除仅用于本次调试的 CA 信任和配置描述文件。
